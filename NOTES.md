# NOTES — source schema findings (verified 2026-08-15)

These repos change shape between seasons. Everything below was verified against
live data on the date above, not assumed. Re-verify at the start of each season.

## 1. SimplifyJobs/Summer2027-Internships

`https://raw.githubusercontent.com/SimplifyJobs/Summer2027-Internships/dev/.github/scripts/listings.json`

- **10.7 MB**, not the ~1 MB expected — ETag conditional fetch is mandatory, not polite.
- 14,353 records — the file holds **every season**, not just Summer 2027.
  Observed `terms` values: Summer 2025→2028, Fall/Winter/Spring variants, and
  `"N/A"` (1,540 records, mostly stale). Only 660 records carry `"Summer 2027"`
  (398 of them active). Season filtering happens on our side via `terms`.
- Fields (all present on all records): `id` (UUID), `source` (curator username —
  "Simplify" or a community contributor, NOT the repo), `company_name`, `title`,
  `active` (bool), `is_visible` (bool), `category`, `terms: list[str]`,
  `date_posted` / `date_updated` (unix epoch ints), `url` (the apply link),
  `locations: list[str]`, `company_url` (simplify.jobs page), `sponsorship`, `degrees: list[str]`.
- `sponsorship` enum observed: `Other` (14,234), `Does Not Offer Sponsorship`,
  `U.S. Citizenship is Required`, `Offers Sponsorship`.
- `category` observed: `AI/ML/Data`, `Software`, `Hardware`, `Product`, `Quant`
  plus a few legacy long-form variants.

## 2. vanshb03/Summer2027-Internships

`https://raw.githubusercontent.com/vanshb03/Summer2027-Internships/dev/.github/scripts/listings.json`

- 401 records, ~230 KB. Same shape as Simplify **minus** `category`, `degrees`,
  `terms`, **plus** `season: str`.
- `season` has **no year**: `Summer` (224), `Fall` (109), `Winter` (62), `Spring` (6).
  The repo is 2027-scoped, so we map `Summer` → `Summer 2027`.
- `company_url` is often `""` here (it's a real company site when set, not a
  simplify.jobs page).

## 3–4. speedyapply/2027-SWE-College-Jobs and 2027-AI-College-Jobs

- **No machine-readable data file exists in either repo.** The markdown tables are
  generated by `.github/scripts` from a private Supabase database (`SUPABASE_URL`
  / `SUPABASE_KEY` env vars) — nothing to fetch there. Markdown parsing is the
  only option, per the fallback rule.
- Default branch is `main`. USA internships live in `README.md`; international in
  `INTERN_INTL.md` (skipped — US search). New-grad files also present (skipped).
- Table sections are delimited by `<!-- TABLE_FAANG_START -->` /
  `<!-- TABLE_QUANT_START -->` / `<!-- TABLE_OTHER_START -->` markers.
  Columns: `Company | Position | Location | Salary | Posting | Age`.
- **No stable listing ID** — we derive `source_id` from a hash of the apply URL.
- `Age` is relative (`3d`, `12h`, `2w`, `1mo`). We approximate `posted_at` as
  `now − age` at first sight; ranking uses our own `first_seen_at` anyway.
- Titles carry their own season ("2027 Summer", "Fall 2026" — yes, Fall 2026
  rows exist in the 2027 repo). Season is parsed from the title; a title with no
  season is given the benefit of the doubt (kept).
- Location cells collapse extras into `+N` ("San Francisco, CA +1").

## Infrastructure

- `raw.githubusercontent.com` honors `If-None-Match` → verified live 304.
- ETags there are strong (`"sha256..."`), stable per file content.

## Gotchas for future seasons

- The in-record `source` field on both JSON sources is the **curator**, not the
  repo — our source tag is assigned by the fetcher, never read from the data.
- Simplify's file will keep growing (it accumulates old seasons). If it gets much
  bigger, consider streaming JSON parsing; today a full `json.loads` is fine.
- If speedyapply ever commits a JSON export, switch `speedyapply.py` to it and
  delete the markdown parser.
